# Project Context

This is a learning project from the Chai Aur Backend series — a basic Express.js backend API.

## Architecture

- **Main entry**: `src/index.js` — connects to MongoDB via custom `src/db/index.js` (isolated connection logic)
- **App setup**: `src/app.js` — Express with CORS, JSON, URL-encoded, cookie-parser middleware; routes mounted at `/api/v1/users`
- **Single route**: `src/routes/user.route.js` — POST `/register` with multer for avatar + coverImage upload
- **Controller**: `src/controllers/user.controller.js` — `registerUser` handler

## Key Observations (for future work)

1. **Controller returns sensitive data** — `registerUser` includes `password` in the response despite the comment about removing it. The `.select('-password')` is applied but then the response includes fields from the original user object.

2. **Multer config is unsafe** — `multer.middleware.js` has no file size limits, no validation, and uploads to local disk without sanitization. Could be exploited for DoS or path traversal.

3. **Missing input sanitization** — No validation on password strength, email format, or username constraints.

4. **Cloudinary utility incomplete** — `src/utils/cloudinary.js` has a commented-out upload function.

5. **Model structure** — `src/models/user.model.js` and `src/models/video.model.js` exist; verify schema alignment with controller.

6. **Middleware stack** — `src/middlewares/multer.middleware.js` configures fields for `avatar` and `coverImage`.

7. **Utility helpers** — `src/utils/asyncHandler.js` wraps controllers; `src/utils/apiErrors.js` and `src/utils/apiResponse.js` provide standardized error/response formatting.

8. **Environment config** — `.env` (not shown) likely contains `PORT`, `MONGODB_URI`, `CORS_ORIGIN`, `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.
